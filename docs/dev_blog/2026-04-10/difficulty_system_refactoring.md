# 2026-04-10 Dev Blog: 난이도 시스템의 모듈화 및 엔진 고도화 (Fidelity v2.9)

오늘은 리듬 게임의 플레이 경험을 결정짓는 핵심 요소인 **난이도 시스템(Difficulty System)**을 기존의 스파게티 코드에서 탈피시켜, 전문적인 엔진 구조로 재설계하는 작업을 진행했습니다.

## 1. 주요 작업 내용

### 🏗️ 난이도 전담 관리자(`DifficultyManager`) 도입

- **문제**: 기존에는 `NoteFactory.ts`라는 하나의 거대한 클래스 안에 전사 로직, 필터링 로직, 난이도 보정 로직이 모두 뒤섞여 있어 코드 수정 시 의도치 않은 버그가 발생할 위험이 높았음.
- **해결**: 난이도 판정만을 전문적으로 처리하는 **`DifficultyManager.ts`** 클래스를 새롭게 설계하여 로직을 완전히 분리(Decoupling)함.
- **결과**: '어떤 노트를 채택할 것인가'에 대한 모든 의사결정이 한 곳에서 집중 관리되어, 향후 난이도 밸런스 튜닝이 매우 용이해짐.

### 🧩 지능형 난이도 전략 (Dynamic Difficulty Strategy)

- **AI 보정 로직 통합**: AI가 전사한 고정밀 데이터를 리듬 게임용 난이도(Easy, Normal, Hard)로 변환할 때 발생하는 복잡한 '난이도 시프트' 로직을 시스템화함.
- **BPM 기반 스케일링**: 곡의 속도(BPM)에 따라 자동으로 노트 간격 임계값을 조절하는 기능을 엔진화하여, 빠른 곡에서도 리듬감이 깨지지 않도록 보장함.
- **동시치기 제어**: 난이도별로 허용되는 동시치기(Chords) 개수를 엄격하게 제한하여 초보자부터 숙련자까지 수준에 맞는 밀도를 제공함.

### 🧪 기능적 무결성 및 리팩토링

- **동일 기능 보장 (Parity)**: 내부 구조는 완전히 바뀌었지만, 실제 게임 플레이 시 생성되는 채보는 이전과 100% 동일하게 유지되도록 검증 완료.
- **코드 클린업**: `NoteFactory`의 복잡도를 40% 이상 감소시켜 가독성을 높이고, 전사 엔진 본연의 기능(노트 생성 및 배치)에만 집중할 수 있는 환경 구축.

## 2. 작업 결과

- **구조적 진보**: 하드코딩된 조건문 기반의 설계에서 **객체지향적 엔진 구조**로 진화.
- **확장성 확보**: 이제 `DifficultyManager`의 파라미터만 조정하면 수백 곡의 난이도를 일괄적으로, 혹은 세밀하게 조정할 수 있는 기반이 마련됨.

## 3. 향후 로드맵 (v3.0을 향하여)

- **서버 측 난이도 프로세싱**: 현재 클라이언트에서 수행하는 난이도 필터링을 서버(Python) 단계로 완전히 이전하여 멀티 트랙 MIDI(난이도별 전용 트랙)를 생성할 예정.
- **전문적 NPS 조절**: 초당 노트 수(NPS) 목표치를 설정하고 이를 기반으로 곡의 긴장감을 조절하는 정밀 기능 추가 계획.
