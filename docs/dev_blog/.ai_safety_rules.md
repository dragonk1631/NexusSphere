# 🛡️ AI Data Handling Rules: "Blog Sanctuary"

이 폴더(`docs/dev_blog`)에 저장된 모든 문서는 사용자가 하루하루 축적한 소중한 기록물입니다. AI인 Antigravity는 해당 데이터를 다룰 때 다음의 엄격한 규칙을 준수해야 합니다.

## 1. 덮어쓰기 엄격 금지 (No Overwrite)

- `Overwrite=true` 속성을 사용하여 기존 파일을 덮어쓰는 행위는 절대 금지됩니다.
- 새로운 내용을 추가하거나 수정할 때는 반드시 `replace_file_content` 또는 `multi_replace_file_content`를 사용하여 특정 영역만 정교하게 수정해야 합니다.

## 2. 작업 전 상태 확인 (View Before Action)

- 파일에 쓰기 작업을 수행하기 전, 반드시 `view_file`을 통해 현재 내용의 무결성을 먼저 확인해야 합니다.
- 파일의 존재 여부와 마지막 작업 내용을 파악하지 않은 상태에서의 쓰기 행위는 금지됩니다.

## 3. 선제적 백업 원칙 (Backup First)

- 파일을 수정하거나 구조를 변경하기 전, 반드시 `scripts/backup_blog.ps1`을 실행하여 현재 상태의 스냅샷을 생성해야 합니다.
- 수정 완료 후에는 `git commit`을 통해 버전 관리 시스템에 즉각 반영해야 합니다.

## 4. 삭제 금지 (No Deletion)

- 사용자의 명시적인 삭제 요청이 없는 한, 블로그 폴더 내의 어떤 파일도 삭제(`rm`, `delete`)할 수 없습니다.
- 실수로 잘못 생성한 파일이라 하더라도, 기존 파일과 이름이 겹친다면 삭제 전 반드시 복구 가능한 백업이 있는지 확인해야 합니다.

---
> [!IMPORTANT]
> **데이터 유실은 AI의 가장 큰 과실입니다.** 이 규칙을 어기는 것은 협업의 신뢰를 깨트리는 행위임을 명심하십시오.
