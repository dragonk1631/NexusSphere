# 2026-04-29 개발 로그: 도감(Collection) UI 안정화 및 스코어링 엔진 고도화

오늘 작업은 사용자 경험의 핵심인 도감 UI의 시각적 완성도를 높이고, 스코어 기록 시스템의 논리적 허점을 보완하는 데 집중했습니다. 특히 랭크 필터링과 통계 데이터 간의 불일치를 해결하고, 다양한 디바이스 환경에서 최적의 정보 밀도를 제공할 수 있도록 레이아웃을 정밀하게 튜닝했습니다.

## 1. Grade-Priority 스코어링 시스템 도입

기존 시스템은 단순히 점수(Score)가 높을 때만 기록을 갱신했으나, 리듬 게임 특성상 더 높은 등급(예: S+)을 획득하는 것이 점수보다 더 중요한 성과인 경우가 많습니다.

- **로직 변경**: 등급별 가중치(`S+: 4, S: 3, A: 2, B: 1, F: 0`)를 부여하여, 점수가 낮더라도 더 높은 등급을 획득하면 기록이 갱신되도록 개선했습니다.
- **서버/클라이언트 동기화**: `ScoreManager.ts`와 서버측 `submit.ts` API에 동일한 가중치 업데이트 로직(SQL `CASE` 문 활용)을 적용하여 데이터 일관성을 확보했습니다.

## 2. 도감 UI 레이아웃 황금 비율 최적화

정보량이 많은 도감 화면에서 시각적 답답함을 해소하고 데이터 가독성을 극대화하기 위해 레이아웃 비중을 전면 재조정했습니다.

- **좌우 5:5 균형**: 통계 섹션과 곡 리스트 섹션의 비중을 동일하게 가져가 안정감을 부여했습니다.
- **수직 공간 재배치 (7:3 -> 6:4 -> 6.5:3.5)**:
  - 상단 통계(Operational Stats)와 하단 랭크 필터(Performance Rating)의 높이 비율을 정밀하게 조정했습니다.
  - 특히 모바일 가로 모드에서는 통계 비중을 6.5로 높여 좁은 화면에서도 데이터가 겹치지 않도록 최적화했습니다.
- **컴팩트 디자인**: 랭크 버튼의 높이를 줄여 불필요한 공백을 제거하고, 남는 공간을 데이터 표시 영역으로 환원했습니다.

## 3. 데이터 무결성 및 필터링 로직 강화

통계 카운터와 실제 필터링 결과가 일치하지 않던 고질적인 문제를 해결했습니다.

- **Effective Grade 시스템**: 100% 정확도(All Perfect) 달성 시 내부적으로 무조건 `S+` 등급으로 취급하는 `getEffectiveGrade()` 헬퍼를 도입했습니다.
- **일관된 카운팅**: 필터링 버튼에 표시되는 숫자와 실제 리스트가 이 헬퍼 함수를 공유하게 함으로써 데이터 불일치를 100% 해결했습니다.

## 4. 시각적 정제 (HUD Refinement)

- **영문 레이블 통일**: HUD의 전문성을 높이기 위해 통계 항목의 한글 설명을 제거하고 `MAX STREAK`, `TOTAL HITS`, `TOTAL PLAYS`, `TOTAL SCORE` 등 영문으로 정제했습니다.
- **반응형 대응**: 모바일 및 태블릿 가로 모드에서 레이아웃이 깨지던 미디어 쿼리 버그를 수정하고, 디바이스별로 최적화된 폰트 크기와 패딩을 적용했습니다.

---

### 기술 스택 및 변경 파일

- **Client**: `CollectionUI.ts`, `ScoreManager.ts`
- **Server**: `submit.ts` (Cloudflare Workers / D1)
- **Style**: Vanilla CSS (CSS Grid / Flexbox)

이번 작업을 통해 NexusSphere의 도감 시스템은 데이터의 정확성과 시각적 완성도 측면에서 한 단계 더 진화했습니다.
