# NexusSphere 인프라 현대화 및 자산 배포 자동화 보고서 (2026-04-15)

오늘 우리는 NexusSphere의 근간이 되는 **자산 전달 인프라(Asset Delivery Infrastructure)**를 완전히 현대화했습니다. 기존의 수동적이고 용량 제한적인 구조를 탈피하여, 전 세계 어디서나 빠르고 안정적으로 작동하는 클라이언트-클라우드 결합 구조를 완성했습니다.

---

## 🚀 1. 핵심 성과 (Key Accomplishments)

### 📦 Cloudflare R2 기반의 자산 저장소 구축

- **Zero Egress Fee**: 데이터 전송료가 무료인 Cloudflare R2를 도입하여, 대용량 사운드폰트 및 음원 전송 비용을 '0원'으로 최적화했습니다.
- **CDN 전용 도메인**: `https://pub-e2b...r2.dev`를 통해 전 세계 어디서든 지연 없는 에셋 로딩이 가능해졌습니다.
- **CORS 보안 설정**: 모바일 및 로컬 개발 환경에서의 원활한 데이터 접근을 위해 정밀한 CORS 정책(`GET`, `HEAD`, `Range` 헤더 허용)을 적용했습니다.

### 🤖 "배포 비서(Deployment Secretary)" 스크립트 개발

- **스마트 해싱 동기화**: `scripts/deploy_assets.mjs`를 통해 로컬 파일과 R2 서버의 상태를 비교, **변경된 파일만** 골라 업로드하는 지능형 배포를 구현했습니다.
- **S3 API 통합**: AWS S3 SDK를 사용하여 `wrangler` CLI의 한계를 극복하고, API 토큰 기반의 안정적인 업로드 파이프라인을 구축했습니다.

### 🎵 오디오 엔진 및 시스템 최적화

- **사운드폰트 클라우드화**: 32MB에 달하는 `default.sf2`를 로컬 저장소에서 제거하고 CDN 호출 방식으로 전환하여, 프로젝트(Git Repo) 용량을 획기적으로 줄였습니다.
- **지능형 경로 해결 (Path Resolution)**: `PathUtils.ts`를 고도화하여 개발 모드와 배포 모드(GitHub Pages) 모두에서 최적의 에셋 경로를 자동으로 찾아가도록 설계했습니다.
- **PWA 오프라인 캐싱**: `VitePWA`의 `CacheFirst` 전략을 통해, 한 번 받은 에셋은 브라우저 창고에 영구 보관되어 두 번째 접속부터는 전송량 0을 달성합니다.

## 🛠️ 2. 환경 설정 및 보안 (Security & Config)

### 🔐 환경 변수 분리 관리 (Environment Hygiene)

- **`.env` (공개)**: CDN 주소와 버전 정보를 포함하여 GitHub 서버가 빌드 시 참조할 수 있게 조치했습니다.
- **`.env.local` (비공개)**: R2 액세스 키와 시크릿 키 등 민감한 정보를 로컬에만 보관하여 보안 유출을 철저히 막았습니다.

### 🧱 인프라 한계 돌파 (LFS & SSL)

- **GitHub LFS 탈출**: GitHub의 용량 제한(1GB)을 우회하기 위해 LFS 추적을 해제하고 R2로 모든 무거운 짐을 옮겼습니다.
- **SSL 개발 환경 안정화**: 모바일 테스트를 위한 HTTPS 환경을 유지하면서도, 개발 중 서비스 워커 충돌로 인한 접속 장애를 완벽하게 해결했습니다.

## 📉 3. 성능 지표 변화

| 항목 | 기존 (AS-IS) | 현재 (TO-BE) | 개선 효과 |
| :--- | :--- | :--- | :--- |
| **초기 로딩 전송량** | 약 50MB+ (매번) | **0MB (캐시 활용 시)** | **99.9% 감소** |
| **Git 저장소 크기** | 32MB (SF2 포함) | **수 KB (텍스트 기반)** | 저장소 슬림화 |
| **배포 소요 시간** | 수동 업로드 (수 분) | 자동 동기화 (수 초) | 생산성 극대화 |
| **네트워크 비용** | 데이터 전송량 빌링 우려 | **전송료 0원 (R2)** | 유지비 제로화 |
