# 개발 블로그: 리듬 게임 오디오 시스템 안정화 및 웹 성능 최적화

## 🚀 오늘 작업의 핵심 요약

오늘은 NexusSphere 리듬 엔진의 사용자 경험(UX)을 결정짓는 핵심 요소인 **오디오 시스템의 안정화**와 **웹 환경에서의 로딩 성능 최적화**를 완벽하게 마무리했습니다.

### 1. 오디오 엔진 초기화 및 안정성 강화

* **문제 해결**: 브라우저의 자동 재생 정책과 엔진 초기화 시점의 충돌로 인해 곡 선택 시 미리보기가 나오지 않거나 에러(`Audio Engine must be initialized first`)가 발생하던 문제를 해결했습니다.
* **조치**: `RhythmGame.init()` 단계에서 오디오 엔진을 선제적으로 초기화하고, 메뉴 진입 시 오디오 상태가 초기화되어 소리가 끊기지 않도록 생명주기(Lifecycle)를 재설계했습니다.

### 2. 초경량 미리보기(Preview) 시스템 구축

* **혁신**: 웹 환경에서 수 메가바이트(MB)에 달하는 MP3 파일을 매번 불러오는 부담을 줄이기 위해, **자동 미리보기 생성 스크립트**를 도입했습니다.
* **결과**:
  * `ffmpeg-static`을 사용하여 모든 곡의 초반 10초 분량을 저용량(64kbps 모노)으로 자동 추출.
  * 평균 **5MB -> 80KB(약 1/60)** 수준으로 용량을 줄여, 웹에서도 미디 파일급 속도로 즉각적인 미리보기가 가능해졌습니다.

### 3. 전문적인 오디오 UX (페이드 및 루프)

* **자연스러운 연결**: 10초 미리보기가 끝날 때 뚝 끊기지 않도록 **3.0초의 부드러운 페이드 아웃**을 적용했습니다.
* **연속 재생**: `onended` 이벤트를 활용한 재귀적 재생 로직과 타이머 동기화(`seek(0)`)를 통해, 반복 재생 시 전송 지연이나 타이밍 어긋남(Drift) 없이 무한히 루프되는 시스템을 완성했습니다.
* **피드백 반영**: 사용자 피드백을 통해 페이드 인을 제거하여 지연 시간을 최소화하고, 루프 연결을 더욱 타이트하게 조정했습니다.

### 4. 코드 품질 및 빌드 안정화

* **CI/CD 대응**: 고도화 과정에서 발생한 TypeScript의 미사용 변수(`unused variables`) 및 린트 에러를 모두 수정하여, 원격 빌드(GitHub Actions 등) 환경에서 안정적으로 배포될 수 있도록 조치했습니다.

* **사용자 경험**: 페이드 시스템 도입으로 인한 오디오 품질의 심미적 상승.
