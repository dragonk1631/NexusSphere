## 1. 배경 및 문제점

기존의 NexusSphere 리듬 엔진은 PWA 환경에서 수백 개의 파일을 개별적으로 캐싱했습니다. 하지만 다음과 같은 치명적인 한계가 발견되었습니다:

1. **네트워크 오버헤드**: 100개 이상의 HTTP 요청이 동시다발적으로 발생하여 서비스 워커의 큐가 마비되는 현상.
2. **동기화 무결성**: 특정 파일 하나만 누락되어도 곡 재생이 실패하지만, 개별 다운로드 방식으로는 전체 '완결성'을 보장하기 어려움.
3. **불투명한 진행 정보**: 사용자에게 단순히 "로딩 중..."이라는 메시지만 보여주는 것은 대용량(100MB+) 처리 시 지루함과 불안감을 유발.

## 2. 해결 전략: "Bundle & Cinematic Feed"

우리는 이러한 문제들을 해결하기 위해 **번들링 기반의 동기화**와 **하이엔드 시각화 피드백**을 결합했습니다.

### 📦 Hybrid Sync (assets_bundle.zip)

개별 파일 요청 대신, 모든 게임 자산을 하나로 합친 `assets_bundle.zip`을 먼저 내려받는 방식을 도입했습니다.

- **속도 극대화**: HTTP/2 환경에서도 100번의 요청보다 1번의 대용량 스트림 요청이 훨씬 빠르고 안정적입니다.
- **원자적 동기화**: 번들을 모두 내려받아 `BinaryVault`(IndexedDB)에 해동(Hydration)하는 과정을 통해 "전부 있거나, 아예 없거나"의 무결성을 확보했습니다.

### 📊 실시간 MB 단위 추적 (Real-time MB Tracker)

단순한 0~100% 게이지는 멈춰있는 것처럼 보일 수 있습니다.

- **구현**: `OfflineDownloadManager`가 스트림의 `Content-Length`를 실시간으로 계산하여 `45.2 MB / 109.1 MB`와 같이 구체적인 수치를 UI에 전달하도록 고도화했습니다.

### 💎 Cinematic Loading UX (Glassmorphism 2.0)

로딩 화면을 단순한 대기 창이 아닌, 게임의 첫인상을 결정짓는 '아트'로 승화시켰습니다.

- **Vibrant Background**: 우중충한 다크 모드에서 벗어나, 리듬 게임의 활기를 담은 화려하고 밝은 Vaporwave 배경으로 교체했습니다.
- **Glassmorphism Panel**: 배경과 정보를 분리하기 위해 내부 글로우와 림 라이트가 적용된 고품질 반투명 패널을 구현했습니다.
- **Breathing Logo**: 정적인 로고 대신, 아주 느린 호흡(1.3 Tempo)과 미세한 스케일 변화가 동기화된 애니메이션을 적용했습니다.

## 3. 구현 내용 요약

- **`OfflineDownloadManager.ts`**: ZIP 번들 스트리밍 다운로드 및 MB 단위 진행률 계산 로직 구현.
- **`generate_bundle.mjs`**: 빌드 타임에 사운드폰트 누락을 방지하는 검증 시스템 추가.
- **`TitleScreen.ts`**:
  - 웅장한 로고 레이아웃 복구 및 "Deep Pulse" 애니메이션 강화.
  - 하이엔드 글래스모피즘 진행률 패널 및 "PRESS START" 버튼 구현.

## 4. 성과 및 향후 과제

이제 NexusSphere 리듬 엔진은 첫 접속 시 **"무엇을, 얼마나 받고 있는지"**를 사용자에게 화려하고 명확하게 보여줍니다. 한 번의 동기화가 끝나면 비행기 모드에서도 완벽한 고음질 리듬 게임을 즐길 수 있습니다.

**향후 계획:**

- IndexedDB 용량 쿼터 초과 시의 자동 캐시 정리(Eviction Policy) 강화.
- 곡별 BGM 미리듣기 파일을 번들에 추가하여 선곡 화면 로딩 속도 개선.
