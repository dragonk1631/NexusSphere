# 모바일 성능 최적화 결과 보고서 (2차): 완벽한 60FPS를 향한 도약

본 보고서는 2차 정밀 최적화 작업을 통해 모바일 환경에서 프레임이 추가적으로 상승한 기술적 원인과 가장 유효했던 처리 항목들을 분석한 문서입니다.

---

## 1. 최적화 결과 요약

- **이전 상태**: 40FPS 후반대 (일시적 50FPS 도달)
- **현재 상태**: **안정적인 50FPS 이상 확보 및 60FPS 고정 시간 대폭 증가**
- **주요 성과**: 시스템 자원 낭비(누수)를 차단하고 GPU의 물리적 연산 한계(Fillrate)를 해결하여 실질적인 렌더링 성능 확보.

---

## 2. 2차 작업 중 가장 유효했던 최적화 (Top 4)

### 🎨 1위: 블렌딩 모드 강제 최적화 (`source-over` 전환)

- **대상**: `BackgroundWorker.ts`
- **유효성**: **가장 높은 성능 기여도**. `lighter`와 `screen` 블렌딩은 GPU가 전/후 픽셀 값을 읽어 연산해야 하므로 모바일 GPU에 엄청난 부하를 줍니다.
- **결과**: 모바일 감지 시 이를 연산이 가벼운 `source-over`로 강제 전환함으로써 GPU가 여유롭게 노트 렌더링에 집중할 수 있는 환경을 조성했습니다.

### 📉 2위: DPR(Device Pixel Ratio) 상한 하향 조정 (1.5 → 1.25)

- **대상**: `ScreenUtils.ts`
- **유효성**: 최신 모바일 기기의 초고해상도 패널은 렌더링해야 할 픽셀 수가 기하급수적으로 많습니다.
- **결과**: DPR 상한을 1.25로 낮춤으로써 **실제 렌더링 면적을 약 30% 절감**했습니다. 이는 GPU의 Fillrate 병목을 직접적으로 해결하는 가장 효과적인 물리적 조치였습니다.

### 🛑 3위: TitleScreen rAF 루프 누수 차단

- **대상**: `main.ts`, `TitleScreen.ts`
- **유효성**: 게임이 시작된 후에도 타이틀 스크린의 애니메이션 루프가 백그라운드에서 몰래 실행되고 있었습니다.
- **결과**: `titleScreen.destroy()` 호출을 통해 불필요한 중복 렌더링 루프를 완전히 파괴했습니다. CPU/GPU가 단 하나의 메인 루프에만 모든 자원을 쏟을 수 있게 되었습니다.

### ⏱️ 4위: `setInterval` 제거 및 타이머 간섭 배제

- **대상**: `CoreAudioEngine.ts`
- **유효성**: 브라우저의 `setInterval`은 `requestAnimationFrame`과 별개의 스레드/타이밍 시스템을 사용하여 미세한 지터(Jitter)를 유발할 수 있습니다.
- **결과**: 오디오 엔진의 진단용 타이머를 제거하여 메인 게임 루프와의 타이밍 경쟁을 없앴습니다.
