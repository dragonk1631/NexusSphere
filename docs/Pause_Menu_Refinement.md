# 일시정지 메뉴 최적화 및 RESUME 기능 안정화 내역

이 문서는 리듬 게임의 일시정지 화면 구성 변경과 재생 재개(RESUME) 시 발생했던 버그 및 그 해결 과정을 정리한 기록입니다.

## 1. 개요 및 배경

플레이어의 편의성을 개선하기 위해 일시정지 화면의 구성을 변경하고, 게임 재개 시 음악과 노트가 멈추는 동기화 문제를 해결하였습니다.

## 2. 발생한 문제

- **버튼 구성의 부적절함**: 'MAIN MENU' 버튼이 불필요하게 포함되어 있었고, 'RESUME' 버튼이 없어 플레이어가 게임으로 복귀하기 위해 반드시 `Esc` 키를 눌러야 하는 불편함이 있었습니다.
- **재개(RESUME) 시 오디오/노트 멈춤**: 일시정지 화면에서 게임 재개 시, 화면은 전환되지만 음악이 재생되지 않고 필드의 노트가 이동하지 않는 버그가 발생했습니다.

## 3. 해결 과정 및 기술적 결정

### 3.1. 일시정지 메뉴 구성 최적화

- **MAIN MENU 제거**: 게임 도중 실수로 메인 메뉴로 나가는 것을 방지하고 구성을 간소화하기 위해 'MAIN MENU' 버튼을 제거했습니다.
- **RESUME 버튼 추가**: 접근성을 높이기 위해 메뉴 최상단에 'RESUME' 버튼을 추가했습니다.
- **버튼 레이아웃 수정 (`PauseRenderer.ts`)**: 버튼 개수와 순서 변경에 따라 렌더러의 버튼 배열을 `RESUME`, `RESTART SONG`, `SONG SELECTION` 순으로 조정했습니다.

### 3.2. RESUME 기능 버그 수정 (`RhythmGame.ts`)

- **원인 분석**: 기존 로직에서 `audioEngine.resume()`을 호출했는데, 이 메서드는 Web Audio `AudioContext`만 재개할 뿐 내부 오디오 시퀀서와 타이머를 다시 구동시키지 않는 문제였습니다.
- **해결 방안 (`RhythmGame.ts`)**: 일시정지 해제 시 `audioEngine.resume()` 대신 `audioEngine.play()`를 호출하도록 수정했습니다. `play()`는 내부적으로 오디오 시퀀서와 시간을 추적하는 `SmoothClock` 타이머를 모두 재시작하도록 구현되어 있어, 음악과 노트를 다시 동기화하여 연주합니다.

## 4. 최종 결과

- 일시정지 화면 순서: **RESUME -> RESTART SONG -> SONG SELECTION**
- 키보드(`Esc`, `Enter`, 화살표) 및 클릭/터치 입력 모두 정상 작동.
- 재개 시 음악 및 노트가 완벽하게 동기화되어 즉시 연주됨.

## 5. 향후 과제

- 일시정지 해제 전 3... 2... 1... 카운트다운 기능을 추가하여 플레이어가 준비할 시간을 확보할 수 있도록 검토 예정입니다.
